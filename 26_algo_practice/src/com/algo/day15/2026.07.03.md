## 문제 1. 야근 도시락 배달 (Day1 S1 복습)

### 문제 요약

- 0번 사무실에서 출발해, 도시락을 요청한 K개 사무실을 모두 방문하는 최소 이동 시간.
- 같은 사무실을 여러 번 지나가도 되고, 간선은 양방향(가중치 C).
- 방문 "순서"를 스스로 정해 총 이동 시간을 최소화 → TSP 구조.
- 제한: 2 ≤ N ≤ 15, 1 ≤ M ≤ N(N-1)/2, 1 ≤ K ≤ N-1, 1 ≤ C ≤ 100.

> ⚠️ 예시 오류: 문제의 예시 출력 9는 사무실 4를 누락한 값이다.
> 실제 정답은 11 (0→2→1→3→4, 비용 2+1+5+3).

---

### 내 풀이 분석

- **풀이 결과**: 성공 — 올바른 알고리즘(Floyd-Warshall + Bitmask DP)으로 완성.

**알고리즘**

Day1에서 DFS로 풀어 시간초과가 났던 문제를, 이번에는 정석대로 다시 풀었다.

1. Floyd-Warshall로 모든 사무실 쌍의 최단거리 `dist[i][j]`를 전처리.
2. 비트마스크 DP로 TSP 해결. 단, **출발지 0번을 targets의 index 0으로 포함**시켜
   K+1개 비트를 쓴다. `dp[1][0] = 0`(0번만 방문, 마지막=0번)에서 시작해
   요청 사무실(index 1..K)을 하나씩 채워 나가고, 최종 마스크 `FILL-1`
   (0번 비트 포함 전체)에서 최솟값을 취한다.

**시간복잡도**

- Floyd-Warshall O(N³) + Bitmask DP O(K² · 2^K). N ≤ 15라 넉넉히 통과.
- Day1의 DFS(사실상 경로 전수 탐색, 최악 지수·팩토리얼급)와 달리 TLE 위험이 없다.

**✅ 잘 짚은 것**

- "같은 방을 여러 번 지나갈 수 있다" → 두 요청지 사이 이동 비용을
  **직접 간선이 아니라 최단거리**로 봐야 한다는 핵심을 짚고 Floyd-Warshall 전처리.
- 방문 순서 최소화가 곧 TSP임을 인지하고 비트마스크 DP로 전환.
- Day1의 실패 원인(DFS 완전탐색)을 정확히 교정했다.

**❌ 문제점 / 개선점**

- **사(死)코드**: 136~138행 `dp[1 << i][0] = dist[0][lunchRoomsIdx[i]]` 초기화는
  0번 비트가 없는 마스크에서 시작하는데, 전이의 `next`는 1..K만 돌아 0번 비트를
  절대 세우지 않는다. 따라서 이 상태들은 답을 읽는 `dp[FILL-1]`(0번 비트 필수)에
  결코 도달하지 못한다. 실제 경로는 전부 `dp[1][0]=0`에서 나오므로 결과는 정답이지만,
  불필요한 초기화다.
- **비트 낭비(경미)**: 0번을 마스크에 포함해 2^(K+1) 상태를 쓴다. 요청지 K개만
  마스킹하면 상태 수가 절반이 된다(모범답안 방식). 정확성엔 영향 없음.

---

### 모범 답안: Floyd-Warshall + Bitmask DP (TSP)

**알고리즘**

1. `dist[a][b]`를 인접 간선으로 초기화한 뒤 **Floyd-Warshall**로 모든 쌍 최단거리 완성.
2. 요청 사무실 K개만 마스킹: `dp[mask][last]` = mask에 속한 요청지를 방문 완료하고
   현재 위치가 `targets[last]`일 때의 최소 비용.
3. 초기값: `dp[1<<i][i] = dist[0][targets[i]]` (0번에서 각 요청지로 첫 이동).
4. 전이: mask에 없는 `next`로 이동, `dp[mask|(1<<next)][next]` 갱신.
5. 답: `min over i of dp[(1<<k)-1][i]`.

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| Floyd-Warshall | O(N³) |
| Bitmask TSP DP | O(K² · 2^K) |
| 합계 | O(N³ + K² · 2^K) |

**공간복잡도**: O(N² + K · 2^K)

---

### 핵심 정리

- "출발점에서 특정 지점들을 모두 방문하는 최소 이동 + 순서를 정할 수 있음 + N,K 작음"
  = **Floyd-Warshall(쌍 최단거리) + Bitmask DP(TSP)** 의 정석 신호. N ≤ 15가 결정타.
- "같은 노드를 여러 번 지나가도 됨" → 두 목표 지점 사이는 직접 간선이 아니라
  **최단거리**로 이어 붙여야 한다(그래서 Floyd-Warshall 전처리가 선행).
- DFS 완전탐색으로 순열을 훑으면 순서 경우의 수가 폭발(TLE). 방문 집합을
  **비트마스크로 상태화**해 중복 부분문제를 메모이제이션하는 것이 핵심.
- 출발점을 마스크에 넣을지는 취향이지만, 넣으면 상태·초기화가 복잡해지고
  사코드가 생기기 쉽다. 요청지 K개만 마스킹하는 편이 깔끔하다.

## 문제 2. 냉장고 털이 루트 (Day1 S2 복습)

### 문제 요약

- 재료 1..N, 방향 간선 A→B(= A 다음에 B 사용 가능)로 이뤄진 방향 그래프.
- 시작 재료는 자유. 순서 안에서 같은 재료가 다시 나오면(사이클 재진입) 실패.
- 실패하지 않는 가장 긴 요리 순서(= **최장 단순 경로**)의 길이를 구한다.
- 그래프에 사이클이 있을 수 있다.
- 제한: 1 ≤ N ≤ 100,000, 0 ≤ M ≤ 200,000.

> ⚠️ 예시 오류: 예시 출력은 4지만, 3→4→2→5→6(5개 노드) 경로가 존재해
> 실제 정답은 5일 가능성이 높다(모범답안 기준).

---

### 내 풀이 분석

- **풀이 결과**: 실패 — `main`이 비어 있고 접근 방향 탐색 주석만 존재(미구현).

**알고리즘**

구현은 없고, 주석에서 방향 그래프·사이클 실패 규칙을 정리한 뒤
"1. 순방향 DFS, 2. 위상정렬 응용 역방향 DFS" 두 갈래를 후보로만 적었다.

**시간복잡도**

- 미구현이라 산정 불가.

**✅ 잘 짚은 것**

- "단방향(방향) 그래프 + 사이클이면 실패"라는 핵심 제약을 정확히 인지.
- **위상정렬**을 해법 후보로 떠올린 점 — SCC 응축 후 DAG 위상 DP로 가는 정석 방향과
  일치한다. (Day1에서는 접근조차 못 했던 것에 비해 방향은 옳게 잡았다.)

**❌ 문제점 / 개선점**

- **미구현**: 그래프 입력 파싱조차 없다. 아이디어를 코드로 옮기지 못했다.
- **사이클 처리 누락**: "사이클이면 유니온 파인드?"에서 멈췄는데, 방향 그래프의
  사이클은 무방향 Union-Find로 못 잡는다. **SCC(강한연결요소)** 로 묶어
  응축 DAG를 만드는 것이 정답 루트다.
- **핵심 함정 간과**: SCC를 하나로 뭉친 뒤 "그 SCC의 노드 수 전부 + 후계"로
  단순 합산하면 **과대 추정**된다(SCC 전체 순회 후 탈출이 항상 가능하지 않음).
  진입/시작 방식을 구분한 이중 DP가 필요하다.

---

### 모범 답안: SCC(Kosaraju) + 응축 DAG + dpEnter/dpStart 이중 DP

**알고리즘**

1. **Kosaraju로 SCC 분해**: 원본 그래프 DFS 종료 순서 기록(반복 DFS로
   N=10^5 스택오버플로 방지) → 역방향 그래프를 그 역순으로 DFS해 SCC 번호 부여.
2. **응축 DAG** 구성: SCC를 노드로, SCC 간 간선만 남긴다(사이클 제거).
3. **위상정렬**(Kahn) 후 **역위상 순서로 DP**(sink → source).
4. 두 상태를 구분:
   - `dpStart[c] = sz[c] + max(dpEnter[후계])` — SCC 내부 어디서든 시작 가능하므로
     최적 시작점을 골라 **sz[c] 전부 순회 후** 탈출.
   - `dpEnter[c] = max(sz[c], 1 + max(dpEnter[후계]))` — 외부에서 진입하면
     진입=탈출 노드가 고정되어, **여기서 끝내거나(sz)** vs **1개만 쓰고 즉시 탈출**.
5. 답 = `max(dpStart[c])`.

**왜 단순 합산이 틀리나**: 예 `{1}→{2,3,4}→{5}→{6}`에서 1+3+1+1=6으로 계산하면,
1→2 진입 후 2→3→4까지 돌면 4→2가 방문 노드라 막혀 탈출 불가. 진입 노드가
고정된다는 제약을 `dpEnter`로 분리해야 정확하다.

**예시 추적** ({1}=A, {2,3,4}=B, {5}=C, {6}=D)

```
dpEnter[D]=1, dpStart[D]=1
dpEnter[C]=max(1,1+1)=2,  dpStart[C]=1+1=2
dpEnter[B]=max(3,1+2)=3,  dpStart[B]=3+2=5   ← 경로 3→4→2→5→6
dpStart[A]=1+max(3,1)=4
정답 = max(5,4,2,1) = 5
```

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| Kosaraju SCC | O(N+M) |
| 응축 DAG + 위상정렬 | O(N+M) |
| 역위상 DP | O(N+M) |
| 합계 | O(N+M) |

**공간복잡도**: O(N+M)

---

### ⚠️ 위 SCC 답안의 한계 (중요)

위 SCC 응축 답안은 `dpStart[c] = sz[c] + ...`에서 **"SCC 하나를 전부 순회 가능"**
이라고 가정한다. 이는 SCC 내부에 **모든 노드를 지나는 단순 경로(해밀턴 경로)** 가
있다는 가정과 같은데, 이는 일반적으로 성립하지 않는다(판정 자체가 NP-complete).

- **반례 (양방향 별)**: 중심 c ↔ 잎 l1, l2, l3 (c→li, li→c). 4노드 한 SCC.
  SCC 답안은 `sz=4` → 답 4. 하지만 실제 최장 단순 경로는 `l1→c→l2`(3노드)뿐이다.
  c를 한 번 쓰면 다른 잎으로 못 건너가므로 4노드 경로는 없다.
- **근본 이유**: 사이클을 포함한 일반 방향 그래프의 **최장 단순 경로는 NP-hard**다.
  N=10^5에서 O(N+M) 최적해는 존재할 수 없다. 즉 SCC 답안은 **과대추정 가능**하며
  이 문제는 (사이클 허용 시) 애초에 다항 최적해가 없다. 예시 출력 4가 이상한 것도
  문제 자체가 잘못 출제됐을 가능성을 시사한다.

---

### ✅ DAG로 한정할 경우의 정확한 정답: 위상정렬 최장 경로 DP

**사이클이 없다면** 모든 경로가 자동으로 단순 경로가 되어, 최장 경로가
위상정렬 DP로 **정확히** O(N+M)에 풀린다. (코드: `Solution2AnswerDAG`)

**알고리즘**

1. Kahn 위상정렬로 순서를 구한다. (`topo.size() < n`이면 사이클 존재 → 전제 위반)
2. `dp[v] = 1 + max(dp[w])` (v→w 간선), 나가는 간선 없으면 `dp[v]=1`.
3. 위상 **역순(sink→source)** 으로 채워 `dp[w]`가 먼저 확정되게 한다.
4. 답 = `max(dp[v])`.

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| Kahn 위상정렬 | O(N+M) |
| 역위상 DP | O(N+M) |
| 합계 | O(N+M) |

**공간복잡도**: O(N+M)

---

### 핵심 정리

- **사이클 유무가 난이도를 가른다**: DAG면 최장 경로 = 위상 DP로 O(N+M) 정확해,
  사이클이 하나라도 있으면 최장 단순 경로는 **NP-hard**(다항 최적해 없음).
- "방향 그래프 + 사이클 재진입 금지 + 최장 경로" = **SCC 응축 → DAG 위상 DP** 정석.
  방향 그래프의 사이클은 Union-Find가 아니라 SCC로 처리한다.
- 최장 단순 경로는 일반 그래프에선 NP-hard지만, **SCC로 DAG로 만들면** 위상정렬
  위 DP로 다항 시간에 풀린다.
- **함정**: SCC를 뭉쳤다고 그 안의 노드를 전부 공짜로 쓸 수 있는 게 아니다.
  외부 진입 시 진입점=탈출점이 묶여 순회 가능 수가 줄어든다 → `dpEnter`/`dpStart`
  분리가 필수.
- N=10^5 그래프 DFS는 **반복(스택) DFS**로 짜서 재귀 스택오버플로를 피할 것.

## 문제 3. 비밀번호 복구 (Day2 S1 복습)

### 문제 요약

- 길이 N, 문자 {A, B, C}로 이뤄진 문자열 중 금지 패턴을 연속 부분문자열로
  포함하지 않는 것을 찾는다.
- 금지 패턴: `AAA`, `BBB`, `CCC`(길이 3), `ABAB`, `BCBC`, `CACA`(길이 4).
- 가능한 것 중 **사전순 최소** 1개를 출력, 없으면 `-1`.

---

### 내 풀이 분석

- **풀이 결과**: 성공 — 정답을 정확히 출력한다. (단, 대형 N에서 메모리 위험)

**알고리즘**

빈 문자열에서 시작해 **BFS(FIFO 큐)** 로 A, B, C 순서로 자식을 확장한다.
각 확장 시 마지막 3·4글자만 검사해 금지 패턴이면 큐에 넣지 않고 가지치기.
길이 N에 처음 도달한 문자열을 출력, 큐가 비면 `-1`.

**시간복잡도**

- 최악 O(3^N)이나 가지치기로 실제 탐색량은 크게 준다.

**✅ 잘 짚은 것**

- **사전순 최소 보장 논리**가 정확하다. 자식을 A→B→C 순으로 offer하고 FIFO로
  꺼내면, 같은 길이(레벨) 안에서 문자열이 사전순으로 정렬돼 유지된다. 따라서
  길이 N에 **처음 도달**한 문자열이 곧 사전순 최솟값이다.
- 금지 패턴이 길이 3~4뿐이라 **마지막 4글자만 검사**하면 충분함을 파악.
- 붙이는 즉시 검사·가지치기로 무효 접두사를 조기 차단.

**❌ 문제점 / 개선점**

- **메모리 폭발 위험**: BFS는 한 레벨의 부분 문자열을 큐에 **동시에** 들고 있어
  최악 O(3^N) 공간이 필요하다. N이 조금만 커져도 MLE 가능. DFS 백트래킹은
  같은 정답을 **O(N) 공간**으로 낸다.
- **문자열 반복 생성**: `c + nc`로 매 확장마다 새 문자열을 만들어 O(길이) 복사가
  누적된다. StringBuilder append/deleteCharAt로 공유하면 복사가 사라진다.

---

### 모범 답안: 백트래킹 (DFS + 가지치기)

**알고리즘**

1. StringBuilder 하나를 공유하며 A→B→C 순으로 한 글자씩 append하며 DFS.
2. append 직후 마지막 3·4글자로 금지 패턴 검사 → 걸리면 그 가지 즉시 포기.
3. 길이 N에 도달하면 그 문자열이 **사전순 최소 정답**(A 우선 탐색이라 첫 완성이 최소).
4. 되돌아올 때 deleteCharAt로 마지막 글자 제거(백트래킹). 끝까지 실패면 `-1`.

**왜 사전순 최소인가**: 각 자리에서 A를 먼저 끝까지 시도하므로, 완성되는 첫
문자열은 항상 가능한 것 중 사전순으로 가장 앞선다. (BFS의 "레벨 내 사전순"과
동일한 결과를 O(N) 공간으로 달성)

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| DFS 탐색 | O(3^N) 최악 (가지치기로 급감) |
| 상태당 패턴 검사 | O(1) (마지막 4글자) |
| 합계 | O(3^N) 최악 |

**공간복잡도**: O(N) — 재귀 스택 + 공유 StringBuilder

---

### 핵심 정리

- "사전순 최소 1개" + "국소 금지 패턴" = **A→B→C 순 DFS 백트래킹**의 정석.
  첫 완성 = 사전순 최소라 별도 정렬·비교가 필요 없다.
- BFS로도 사전순 최소를 낼 수 있지만(레벨 내 사전순 유지), **큐가 지수적으로
  커진다**. 같은 결과를 DFS는 O(N) 공간으로 내므로, "1개만 찾으면 되는" 문제엔
  BFS보다 DFS가 유리하다.
- 금지 패턴 길이가 유한(≤4)하면 **꼬리 몇 글자만 검사**하면 되므로 검사 O(1).
- 문자열을 매번 새로 만들지 말고 **StringBuilder append/delete로 공유**해 복사 제거.

## 문제 4. 보석 금고 경로 (Day2 S2 복습)

### 문제 요약

- N×N 격자, (0,0)에서 시작해 상하좌우로 이동하며 **정확히 K개 칸** 방문(시작칸 포함).
- 같은 칸 재방문 금지, 장애물 `#` 방문 금지.
- 방문 칸 가치 합이 **정확히 S**, 연속 세 칸이 **모두 증가(a<b<c)/모두 감소(a>b>c)** 금지.
- 조건을 만족하는 **경로의 개수**를 출력.
- 제한: 3 ≤ N ≤ 8, 1 ≤ K ≤ 20, 0 ≤ S ≤ 100.

---

### 내 풀이 분석

- **풀이 결과**: 부분 성공 — 구조·가지치기는 정확하나 **시작칸 방문처리 버그**로
  과대 카운트 가능.

**알고리즘**

(0,0)부터 4방향 DFS 백트래킹. `cnt==k`일 때 `valueSum==s`면 1 반환.
합 초과(`valueSum > s`)·장애물·범위·방문 칸을 가지치기하고, 직전 칸 가치 `prev`를
넘겨 연속 3칸 단조 여부를 좌표값으로 직접 검사한다.

**시간복잡도**

- 최악 O(4^K), 가지치기로 대폭 감소. N≤8, K≤20이라 완전탐색 타당.

**✅ 잘 짚은 것**

- **단조 검사 시점이 정확**하다. `prev`를 시작칸(-1)부터 넘겨, 시작칸을 포함한
  **모든 연속 3칸**을 빠짐없이 검사한다(첫 3칸 누락 실수를 피함).
- `cnt==k` 종료로 시작칸 포함 **정확히 K칸**을 센다(K+1칸 실수 회피).
- 가치 ≥ 0을 이용한 `valueSum > s` 합 초과 가지치기, 장애물(-1) 처리 정확.
- 다음 칸을 마킹→재귀→해제하는 백트래킹 자체는 올바르다.

**❌ 문제점 / 개선점**

- **★ 시작칸 방문처리 누락(핵심 버그)**: `main`에서 `v[0][0]=true`를 하지 않는다.
  DFS가 "현재 칸"이 아니라 "다음 칸(`v[ny][nx]`)"만 마킹하는 구조라, 시작칸 (0,0)은
  끝까지 방문 배열에 올라가지 않는다. 그 결과 경로가 **(0,0)으로 되돌아올 수 있어**
  (예: K≥3에서 (0,0)→(0,1)→(0,0)) 같은 칸을 두 번 방문한 경로가 카운트된다.
  → **해결**: `main`에 `v[0][0]=true` 한 줄 추가, 또는 모범답안처럼
  **dfs 진입 시 현재 칸을 마킹**(`vis[y][x]=true`)하면 시작칸까지 자동 포함된다.
  (예제 `4 6 18`은 우연히 0이 나올 수 있어 버그가 드러나지 않을 뿐이다.)

---

### 모범 답안: DFS 백트래킹 (완전탐색 + 가지치기)

**알고리즘**

1. `dfs(y, x, cnt, sum, prev)` — 진입 즉시 `vis[y][x]=true`로 **현재 칸**을 마킹
   (시작칸도 이 시점에 방문 처리되어 재방문 불가).
2. `sum > s`면 즉시 중단(가치 ≥ 0이라 더 줄지 않음).
3. `cnt==k`면 `sum==s`일 때만 카운트.
4. 4방향으로 범위·방문·장애물·연속3칸 단조를 검사해 통과하는 칸만 재귀.
5. 반환 시 `vis[y][x]=false`로 해제.

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| DFS 완전탐색 | O(4^K) 최악 |
| 상태당 검사 | O(1) |
| 합계 | O(4^K) 최악 (가지치기로 급감) |

**공간복잡도**: O(N²) 방문 배열 + O(K) 재귀 스택

---

### 핵심 정리

- 경로 **개수 세기 + 작은 격자(N≤8) + 재방문 금지** = DFS 백트래킹 완전탐색 정석.
- **시작칸도 하나의 방문 칸**이다. "현재 칸을 dfs 진입 시 마킹"하는 패턴이
  "다음 칸만 마킹"보다 안전하다 — 후자는 시작칸 마킹을 main에서 따로 해줘야 하고
  잊으면 원점 재방문 버그가 난다.
- 연속 3칸 제약은 **직전 칸 값(prev)만 넘기면** 좌표값으로 O(1) 검사 가능. prev를
  시작칸부터(-1) 넘겨 첫 3칸까지 빠짐없이 검사할 것.
- 종료 조건은 `cnt==K`(방문 칸 수)로 잡아 시작칸 포함 정확히 K칸을 세도록 한다.
