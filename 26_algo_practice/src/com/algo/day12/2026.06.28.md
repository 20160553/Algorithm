## 문제 1. 최단경로

### 문제 요약

- 방향 그래프에서 시작점 K로부터 모든 정점까지의 최단 경로를 구한다.
- 모든 간선 가중치는 10 이하의 자연수(양수) → 다익스트라 적용 가능.
- 두 정점 사이에 다중 간선 존재 가능.
- 도달 불가능한 정점은 `INF`, 시작점은 `0` 출력.
- 제한: V ≤ 20,000, E ≤ 300,000, 시간 1초 / 메모리 256MB

---

### 내 풀이 분석

- **풀이 결과**: 부분 성공 — 작은 예제는 통과 가능하나 제약 조건에서 MLE/TLE로 실패

**알고리즘**

다익스트라로 접근한다는 방향은 맞았으나, 인접 리스트(`roads`)와 별개로 `costs[V+1][V+1]` **2차원 거리 행렬**을 만들고, PQ를 돌면서 매 poll마다 모든 중간 정점 `mid`와 도착 정점 `dest`를 이중 루프로 순회해 `costs[p][mid] + costs[mid][dest]`로 갱신하는 **플로이드 변형 형태**가 섞여 있다. 표준 다익스트라(인접 간선만 완화)와는 다른 구조다.

**시간복잡도**

- 메모리: `costs[V+1][V+1]` = 약 `20001² ≈ 4×10⁸` int → **약 1.6GB** → 256MB 제한 초과(MLE)
- 시간: PQ에서 꺼낼 때마다 `O(V²)` 이중 루프 → 전체 `O(?·V²)`로 사실상 통과 불가(TLE)

**✅ 잘 짚은 것**

- 양수 가중치 단일 출발점 최단경로 → 다익스트라라는 판단은 정확
- `INF = Integer.MAX_VALUE / 2`로 덧셈 오버플로 방지
- 다중 간선을 `Math.min`으로 작은 비용만 보관
- 인접 리스트(`roads`)도 별도로 구성

**❌ 문제점 / 개선점**

- **MLE**: `V×V` 거리 행렬은 V=20,000에서 메모리 한계를 크게 초과. 거리는 `dist[V+1]` **1차원 배열**이면 충분하다.
- **TLE**: 매 poll마다 `O(V²)` 순회. 다익스트라는 꺼낸 정점의 **인접 간선만** 완화해야 `O(E log V)`가 된다.
- **낡은 항목 스킵 누락**: `if (d > dist[node]) continue;`가 없어 PQ에 중복 항목이 쌓이고 같은 정점을 반복 처리한다.
- **인접 리스트 미사용**: `roads`를 만들어 놓고 정작 완화에는 `costs` 행렬을 쓴다 — 설계가 이중화되어 혼란.
- 알고리즘이 다익스트라/플로이드 어느 쪽도 정석이 아니라 **정확성 보장이 안 된다**.

---

### 모범 답안: 다익스트라 (인접 리스트 + 최소 힙)

**알고리즘**

1. 그래프를 인접 리스트 `graph[u] = {도착정점, 비용}` 로 구성.
2. `dist[]`를 INF로 초기화, `dist[start] = 0`, PQ에 `{start, 0}` 삽입.
3. PQ에서 거리 최소 정점을 꺼내고, `d > dist[node]`면 낡은 항목이므로 스킵.
4. 인접 간선만 완화: `nd = d + w < dist[to]`면 갱신 후 PQ에 삽입.
5. 종료 후 `dist[i]`가 INF면 `INF`, 아니면 값 출력.

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| 그래프 입력 | O(E) |
| 다익스트라(힙) | O(E log V) |
| 합계 | O(E log V) |

**공간복잡도**: O(V + E)

---

### 핵심 정리

- **양수 가중치 단일 출발점 최단경로 = 다익스트라(힙), O(E log V)**. 음수 간선이면 벨만-포드.
- 거리 저장은 **1차원 `dist[]`** 로 충분하다. `V×V` 행렬은 모든 쌍 최단경로(플로이드)에서나 쓰며, V가 크면 메모리부터 터진다.
- 다익스트라 핵심 3요소: ① 인접 리스트, ② 거리 기준 최소 힙, ③ **낡은 항목 스킵(`d > dist[node]`)**.
- 완화는 항상 **꺼낸 정점의 인접 간선만** — 전체 정점을 순회하는 순간 다익스트라가 아니다.

## 문제 2. 최소 스패닝 트리

### 문제 요약

- 무방향 그래프의 모든 정점을 연결하면서 가중치 합이 최소인 트리(MST)를 구한다.
- 간선 가중치 C는 **음수 가능**(절댓값 ≤ 1,000,000), 임의의 두 정점 사이 경로 존재(연결 그래프).
- MST 가중치 합은 int 범위 내 보장.
- 출력: MST 가중치 합.
- 제한: V ≤ 10,000, E ≤ 100,000

---

### 내 풀이 분석

- **풀이 결과**: 성공 — 크루스칼 정석 구현으로 정상 동작

**알고리즘**

크루스칼: 간선을 가중치 오름차순 정렬 → 싼 간선부터 보며 두 끝점이 다른 집합이면 채택(비용 누적), 같은 집합이면 사이클이므로 스킵. 사이클 판별은 **유니온 파인드(경로 압축)** 로 처리.

**시간복잡도**

- 정렬 `O(E log E)`가 지배, 유니온 파인드 연산은 `O(α(V))` → 전체 `O(E log E)`

**✅ 잘 짚은 것**

- MST → 크루스칼이라는 판단과 "정렬 + 사이클 스킵" 골격이 정확
- `find`에 **경로 압축**(`return p[a] = find(...)`) 적용 — 효율적
- `union`이 합쳐졌는지 boolean으로 반환해 채택 여부를 깔끔하게 분기
- 음수 간선이 있어도 합이 int 범위를 넘을 수 있는 누적을 **`long answer`** 로 안전 처리

**❌ 문제점 / 개선점**

- 기능상 버그는 없음. 사소한 개선만:
  - `union by rank/size` 미적용 — 경로 압축만으로도 충분히 빠르지만, 둘을 함께 쓰면 거의 상수 시간.
  - **조기 종료** 없음 — 채택 간선이 `V-1`개가 되면 트리가 완성되므로 `break` 가능(미미한 최적화).
  - 입력 파싱에 `split(" ")` + 스트림 사용 — 간선 10만 개라 무난하나, `StringTokenizer`가 더 빠르고 가비지가 적다.

---

### 모범 답안: 크루스칼 (Union-Find + Sorting)

**알고리즘**

1. 모든 간선을 `(A, B, C)` 로 읽어 가중치 `C` 오름차순 정렬.
2. `parent[i] = i`로 유니온 파인드 초기화.
3. 정렬된 간선을 순회하며 `union(A, B)`가 성공(다른 집합)이면 비용 누적.
4. 채택 간선이 `V-1`개가 되면 트리 완성 → 조기 종료.
5. 누적 합 출력(`long`).

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| 간선 정렬 | O(E log E) |
| 유니온 파인드 | O(E·α(V)) |
| 합계 | O(E log E) |

**공간복잡도**: O(V + E)

---

### 핵심 정리

- **MST = 크루스칼(간선 정렬 + 유니온 파인드) 또는 프림(힙)**. 간선 위주면 크루스칼, 정점/밀집 그래프면 프림.
- 크루스칼 핵심: **정렬한 싼 간선부터, 사이클 안 생기면 채택**. 사이클 판별 = 두 정점이 같은 집합인지.
- 유니온 파인드 최적화 2종: **경로 압축** + **union by rank/size**. 함께 쓰면 거의 상수 시간.
- 가중치가 음수이거나 누적이 클 수 있으면 합은 **`long`** 으로 받는다.
- 채택 간선 `V-1`개면 MST 완성 → 조기 종료로 남은 정렬 간선 순회 생략 가능.
