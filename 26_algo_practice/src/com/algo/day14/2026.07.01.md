## 문제 1. 네트워크 복구

### 문제 요약

- N개의 컴퓨터, M개의 회선(가중치 C). 모든 회선을 끊은 상태에서 다시 복구한다.
- 조건 ① 최소 개수의 회선만 복구(= 스패닝 트리, N-1개)해 전체가 연결되어야 한다.
- 조건 ② 슈퍼컴퓨터(1번)에서 각 컴퓨터까지의 **최단 시간**이 원래 네트워크보다
  커지면 안 된다.
- 제한: 1 ≤ N ≤ 1,000, 1 ≤ C ≤ 10

---

### 내 풀이 분석

- **풀이 결과**: 실패 — 알고리즘 선택 오류(MST) + 코드 버그.

**알고리즘**

간선을 비용순으로 정렬해 Union-Find로 사이클을 피하며 잇는 **Kruskal MST**를
구현했다. 채택된 간선을 개수와 함께 출력한다.

**시간복잡도**

- 정렬 O(M log M) + Union-Find O(M α(N)). 복잡도 자체는 문제없다.

**❌ 문제점 / 개선점**

- **알고리즘이 문제와 다르다**: 이 문제의 핵심 조건 ②는 "1번에서의 최단거리 보존"이다.
  MST는 **간선 총합**을 최소화할 뿐, 특정 정점(1번)에서의 최단거리를 보장하지 않는다.
  우회 경로가 더 싸서 MST에 뽑혀도, 1번→해당 정점 거리는 원본보다 늘 수 있어 오답이다.
  이 문제는 **MST가 아니라 최단경로 트리(Shortest Path Tree)** 문제다.
- **간선 저장 버그**: `edges.add(new int[]{edge[1], edge[2]})`로 A(=edge[0])를 버리고
  B, C만 저장했다. 정점 하나(A)가 통째로 사라진다.
- **정렬 인덱스 out-of-bounds**: 위처럼 2칸 배열을 저장해 놓고
  `Comparator.comparingInt(o -> o[2])`로 인덱스 2를 참조 → `ArrayIndexOutOfBounds` 예외.
- 결과적으로 `union(e[0], e[1])`도 정점이 아닌 (B, C)를 정점으로 오해해 잇는다.

---

### 모범 답안: Dijkstra + 최단경로 트리

**알고리즘**

1. 1번을 시작점으로 **Dijkstra**를 돌려 `dist[v]`(1→v 최단시간)를 구한다.
2. 각 정점 v(2..N)마다 인접 간선 중 `dist[u] + w(u,v) == dist[v]`를
   만족하는 간선 (u, v) **하나만** 골라 복구 목록에 넣는다.
3. 이렇게 뽑은 N-1개 간선은 (a) 트리이면서 (b) 1번 기준 모든 최단거리를 그대로
   보존한다. 개수 N-1과 간선들을 출력한다.

**왜 성립하는가**: Dijkstra 최단거리는 항상 "직전 정점 u의 최단거리 + 간선"으로
만들어진다. 각 정점이 자기 최단거리를 만든 간선 하나씩만 채택하면, 1번에서 모든
정점으로 가는 최단경로가 그 트리 안에 그대로 들어 있게 된다.

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| Dijkstra | O((N + M) log N) |
| 간선 선택 | O(N + M) |
| 합계 | O((N + M) log N) |

**공간복잡도**: O(N + M)

---

### 핵심 정리

- "최소 회선 + 1번(특정 정점)에서의 최단거리 보존" = **최단경로 트리(SPT)** 신호.
  MST와 헷갈리기 쉬운 대표 함정 문제다. MST는 총합 최소, SPT는 시작점 거리 최소.
- SPT 만드는 정석: Dijkstra로 dist 구한 뒤 각 정점마다
  `dist[u] + w == dist[v]`인 간선 1개씩 채택.
- 입력 파싱 시 A B C 세 값을 온전히 저장했는지, 정렬/접근 인덱스가 배열 길이 안에
  드는지 반드시 확인.

## 문제 2. 놀이 공원

### 문제 요약

- N명이 한 줄로 서서 M종류의 1인승 놀이기구를 기다린다. 기구 i는 운행시간 d_i분.
- 기구가 비면 줄 맨 앞 아이가 탑승하고, 동시에 여러 개가 비면 **번호가 작은 기구** 우선.
- 모두 빈 상태에서 시작할 때, **마지막(N번째) 아이**가 타는 기구 번호를 구한다.
- 제한: 1 ≤ N ≤ 2,000,000,000, 1 ≤ M ≤ 10,000, 1 ≤ d_i ≤ 30 / 2초, 128MB

---

### 내 풀이 분석

- **풀이 결과**: 실패 — 본 로직 미작성(주석만). 접근 방향도 재검토 필요.

**알고리즘**

`main`은 비어 있고, 주석에서 "최소공배수(LCM)를 구해 그 주기까지만 배치하고
N % LCM으로 환원한다"는 아이디어를 탐색하다 멈췄다.

**시간복잡도**

- 미완성이라 산정 불가.

**✅ 잘 짚은 것**

- 기구별 탑승이 주기적(각 d_i 배수 시각)이라는 성질을 인지한 점.
- N이 20억이라 직접 시뮬레이션이 불가능함을 감지한 점.

**❌ 문제점 / 개선점**

- **LCM 접근의 한계**: 기구가 최대 10,000개라 d_i들의 LCM이 천문학적으로 커진다
  (2·3·5·7·… 조합). 주기로 환원하는 전략이 성립하지 않는다.
- 값(아이 번호)이 아니라 **시간(분)** 을 다뤄야 한다. 시각 T까지 탑승 인원은 T에 대해
  **단조 증가** → 이분 탐색 대상이다.
- N ≤ M인 경계(첫 M명이 시각 0에 1..M번을 그대로 탑승 → 답 N)를 놓치기 쉽다.

---

### 모범 답안: 시간에 대한 이분 탐색

**알고리즘**

1. N ≤ M이면 첫 M명이 시각 0에 번호순으로 타므로 답은 N.
2. 기구 i는 시각 0, d_i, 2d_i, … 마다 한 명씩 태운다. → **시각 T까지 탑승한 총 인원**
   `boarded(T) = Σ(T / d_i + 1)` (T에 대해 단조 증가).
3. `boarded(T) >= N`을 만족하는 **최소 시각 T**를 이분 탐색한다.
4. `cntBefore = boarded(T-1)` = T 직전까지 탑승 수. `remaining = N - cntBefore`는
   "시각 T에 몇 번째로 타는 아이가 N번째인가".
5. 기구를 번호 오름차순으로 보며 `T % d_i == 0`(시각 T에 비는 기구)마다 remaining을
   1씩 줄이고, 0이 되는 기구 번호가 정답.

**예시 추적** (N=22, M=5, d=[1,2,3,4,5])

```
boarded(7) = 8+4+3+2+2 = 19  (< 22)
boarded(8) = 9+5+3+3+2 = 22  (>= 22)  → 최소 T = 8
remaining  = 22 - 19 = 3
T=8에 비는 기구(8 % d == 0): 1번, 2번, 4번  (3번·5번은 나머지 발생)
  1번 → remaining 2, 2번 → remaining 1, 4번 → remaining 0  ⇒ 정답 4
```

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| 이분 탐색 | O(log(maxT)), maxT ≈ 30·N |
| 스텝마다 boarded 계산 | O(M) |
| 합계 | O(M log(maxT)) |

**공간복잡도**: O(M)

---

### 핵심 정리

- "N이 20억, 어떤 값을 직접 구하기엔 너무 큼" + "시각에 따라 단조 증가하는 양" →
  **답(시간)을 이분 탐색**(parametric search)하는 전형.
- 주기 신호(LCM)가 보여도 개수가 많으면 LCM은 폭발한다. LCM 대신
  "시각 T까지 누적 개수 Σ(T/d_i + 1)"라는 닫힌 식을 세워 이분 탐색에 태운다.
- 이분 탐색으로 경계 시각 T를 찾은 뒤에는, 그 시각에 **동점으로 비는 기구를
  번호 순으로 세어** 정확한 위치를 집어낸다.
- N ≤ M 같은 경계 케이스를 먼저 처리할 것.
