## 문제 1. 그림 거래 (최대 소유자 수)

### 문제 요약

- 1번 아티스트(0번 노드)가 그림을 0원에 얻은 뒤, 조건을 지켜 계속 되판다.
- 조건 ①: 팔 때는 자신이 산 가격보다 비싼(≥) 가격에 팔아야 한다.
- 조건 ②: 같은 사람이 그림을 두 번 살 수 없다(= 한 번 소유한 사람은 재소유 불가).
- `price[i][j]` = i가 j에게서 살 때의 가격(문자 '0'~'9').
- 잠시라도 소유했던 사람 수의 **최댓값**을 출력. 제한: 2 ≤ N ≤ 15.

> ⚠️ 예시 오류(주의): 지문은 "크거나 같은(≥)"이라 하지만, 예제(3, 위 행렬)에서
> 0→1→2 체인이 ≥ 기준으론 유효(가격 0,1,1)해 답이 3이 나온다. 실제 예제 출력은 2이므로
> **가격은 "초과(>)"로 엄격 증가**해야 재현된다. 모범답안은 예제(=2)에 맞춰 strict로 구현했다.

---

### 내 풀이 분석

- **풀이 시간**: 미상(코드 주석에 없음)
- **풀이 결과**: 부분 성공 — 비트마스크 DP **골격은 잡았으나 핵심 로직이 미완/버그**로 오답.

**알고리즘**

"N ≤ 15 → 비트마스킹", "외판원(TSP) 응용?"까지 방향은 옳게 잡고
`dp[mask][last]`, `dp[1][0]=0` 시작 프레임을 세웠다. 하지만 전이 규칙과 정답 집계가 어긋난다.

**시간복잡도**

- 구조상 O(2^N · N²)이나, 로직이 틀려 정답을 내지 못한다.

**✅ 잘 짚은 것**

- N ≤ 15에서 **비트마스크 DP**를 떠올린 점, `dp[mask][last]` 상태 설계와 `dp[1][0]=0` 시작.
- "지불가를 min으로 유지"(`dp[nm][next] = min(...)`)하려는 발상 자체는 지배 관계상 옳다.

**❌ 문제점 / 개선점**

- **★ 정답 집계가 틀림**: `answer = Math.max(answer, next)`는 노드 **번호**의 최댓값을 담는다.
  구하려는 건 **소유자 수**이므로 `Integer.bitCount(nm)`(방문 집합 크기)여야 한다.
  현재 코드는 대부분 입력에서 그냥 `N-1`을 출력한다.
- **★ 가격 증가 조건 미검사**: 전이에서 `price[next][prev]`가 prev의 구매가보다 큰지
  검사하지 않는다. 조건 ①(비싸게 판다)을 전혀 강제하지 못해 모든 전이가 허용된다.
- **★ dp 초기화 범위 버그**: `for (i<n) Arrays.fill(dp[i], INF)`는 dp의 **앞 n행만** 채운다.
  dp는 2^N행이므로 나머지 대다수 상태가 INF가 아닌 0으로 남아 min 비교가 깨진다.
- **가격 변환 누락**: `dist[i][j] = str.charAt(j)`로 **아스키 코드('0'=48)** 를 저장한다.
  비교의 상대 순서는 우연히 보존되지만 `- '0'`으로 정수화하는 게 정석.
- **미완성**: 위 로직들이 맞물려야 답이 나오는데 어느 하나도 완결되지 않았다.

---

### 모범 답안: 비트마스크 DP (가격 증가 최장 체인)

**알고리즘**

1. `dp[mask][last]` = mask 집합을 거쳐 `last`가 마지막 소유자일 때 **last가 지불한 최소 가격**.
2. 시작: `dp[1][0] = 0` (0번이 0원에 그림을 얻음). 그 외 INF.
3. 전이: `next`가 `prev`에게서 `price[next][prev]`에 산다.
   그 가격이 `dp[mask][prev]`보다 **커야** 유효(비싸게 되판다). 새 상태 갱신 시 min 유지.
4. 답: 도달 가능한 모든 상태에서 `popcount(mask)`의 최댓값(= 소유자 수).

> 지불가를 낮게 유지할수록 이후 거래 여지가 커지므로, 같은 `(mask, last)`에서는
> **최소 지불가**가 지배적이다 → min 유지가 정당하다.

**예시 추적** (3 / `022 101 110`, 0-index)

```
시작 dp[001][0] = 0
 0→1: price[1][0]=1 > 0  → dp[011][1]=1   (소유자 2명)
 0→2: price[2][0]=1 > 0  → dp[101][2]=1   (소유자 2명)
 1→2: price[2][1]=1 > 1 ? 아니오(strict) → 막힘
 2→1: price[1][2]=1 > 1 ? 아니오          → 막힘
=> 최대 소유자 수 = 2
```

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| 상태 수 | O(2^N · N) |
| 상태당 전이 | O(N) |
| 합계 | O(2^N · N²) |

**공간복잡도**: O(2^N · N)

---

### 핵심 정리

- "특정 시작점에서 방문 집합을 넓혀가며 최댓값 + N ≤ 15" = **비트마스크 DP**의 전형 신호.
- **정답 집계 대상**을 명확히: 여기선 노드 번호가 아니라 **방문 집합 크기(popcount)** 다.
- **전이 유효성(제약 조건)** 을 반드시 코드로 강제할 것 — 여기선 "가격 증가"가 그 핵심.
- **min-지불가 지배**: 뒤 선택지를 넓히는 값(여기선 낮은 가격)을 상태에 저장해 두면
  "최장 체인"류 문제를 탐욕적 폭발 없이 DP로 접는다.
- `dp` 초기화는 **전체 상태 수(2^N)** 기준으로. 부분만 채우면 조용한 버그가 된다.
- 지문의 부등호(≥/>)가 예제와 어긋나면 **예제 출력을 정답 기준**으로 삼아 맞춘다.

## 문제 2. 수영장 만들기 (빗물 트래핑 II)

### 문제 요약

- N×M 격자, 각 칸 높이 1~9. 가운데에 물을 부으면 낮은 곳으로 흐르고 벽을 넘으면 밖으로 나간다.
- 경계(맨 바깥 칸)에 닿은 물은 그대로 빠져나가 **고이지 않는다**.
- 각 칸에 고일 수 있는 물의 총량을 구한다.
- 제한: 1 ≤ N, M ≤ 50, 높이 1 ≤ h ≤ 9.

---

### 내 풀이 분석

- **풀이 결과**: 실패 — `main`이 비어 있고 접근 아이디어 주석만 존재(미구현).

**알고리즘**

"빡구현/BFS 아닌가?"로 보고 "2→9까지 수위별 BFS를 돌리고, 0행·0열(경계)에 닿으면
카운트 안 함"을 후보로 적었다. 코드는 없다.

**시간복잡도**

- 미구현이라 산정 불가.

**✅ 잘 짚은 것**

- **경계에 닿으면 물이 빠져나간다**는 핵심 규칙을 정확히 인지(0행/0열 접근 시 미카운트).
- 낮은 곳부터 물이 차오른다는 흐름을 BFS로 잡으려 한 방향 감각.

**❌ 문제점 / 개선점**

- **미구현**: 입력 파싱조차 없다. 아이디어를 코드로 옮기지 못했다.
- **"2→9 수위별 BFS 반복"의 함정**: 각 수위마다 전체 격자를 다시 훑으면 경계 연결·재방문
  판정이 번거롭고 중복 계산이 많다. 수위가 칸마다 다르므로 단순 반복 BFS는 관리가 어렵다.
  → **경계에서 시작하는 최소 힙(우선순위 큐)** 한 번의 확장이 정석이다.

---

### 모범 답안: 빗물 트래핑 II (경계 시작 우선순위 큐)

**알고리즘**

1. 물은 자신을 둘러싼 **가장 낮은 벽**을 넘어야 탈출한다.
   ⇒ 칸의 담수량 = `max(0, (둘러싼 최소 벽) - (칸 높이))`.
2. **최소 힙**에 모든 경계 칸을 `{높이, r, c}`로 넣고 visited 표시(경계는 물이 빠져나감).
3. 힙에서 **가장 낮은 벽**을 꺼내 이웃으로 확장:
   - 이웃 담수량 `+= max(0, wall - h[이웃])`
   - 이웃의 새 벽 높이 `= max(wall, h[이웃])` 로 힙에 push.
4. 힙이 빌 때까지 반복, 누적 담수량이 정답.

> 낮은 벽부터 확장하므로, 각 칸에는 **가장 낮은 탈출 경로의 벽 높이**가 먼저 확정된다.
> 이것이 "그 칸을 둘러싼 최소 벽"과 정확히 일치한다.

**예시 추적** (예제 2: 4×6 / `999999 / 955119 / 955119 / 999999`)

```
내부 칸: (1,1)(1,2)(1,3)(1,4) = 5,5,1,1
         (2,1)(2,2)(2,3)(2,4) = 5,5,1,1
둘러싼 경계 벽은 전부 9 → 최소 탈출 벽 = 9
담수 = (9-5)+(9-5)+(9-1)+(9-1) [row1]  +  동일 [row2]
     = (4+4+8+8) + (4+4+8+8) = 24 + 24 = 48  ✓
```

**시간복잡도**

| 단계 | 복잡도 |
|------|--------|
| 경계 초기화 | O(N·M) |
| 힙 확장(칸당 1회 push/pop) | O(N·M·log(N·M)) |
| 합계 | O(N·M·log(N·M)) |

**공간복잡도**: O(N·M) — visited 배열 + 힙

---

### 핵심 정리

- "격자에 물을 부어 고이는 양 + 경계로 새어나감" = **빗물 트래핑 II(2D trapping rain water)**.
  1D의 "양옆 최댓값" 대신 **경계에서 시작하는 최소 힙**으로 최소 벽을 전파하는 게 정석.
- 담수량 공식 하나로 요약된다: `max(0, 둘러싼 최소 벽 - 칸 높이)`.
- **가장 낮은 벽부터** 확장해야 각 칸에 올바른 "최소 탈출 벽 높이"가 먼저 박힌다
  (그래서 BFS/큐가 아니라 **우선순위 큐**여야 한다).
- 경계 칸은 처음부터 visited 처리하고 물을 0으로 둔다 — "밖으로 새는 물은 안 센다"의 구현.
